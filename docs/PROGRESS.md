# HireFlow — מצב הפרויקט והמשכיות

עדכון אחרון: 2026-10-31, לפי אזור הזמן Asia/Jerusalem.

**מצב נוכחי: שלב 0 ותת־משימה 1.1 הושלמו. קיים שלד pnpm workspace ללא תלויות וללא אפליקציות. יש לעצור לפני 1.2 ולהמתין לבקשת המשתמש להמשיך.**

## 1. הוראות לתחילת כל משימה ולסיומה

1. בתחילת כל משימה קרא במלואם את [PRODUCT.md](PRODUCT.md), [ARCHITECTURE.md](ARCHITECTURE.md) ואת המסמך הזה. בדוק גם הוראות `AGENTS.md` אם נוספו, ואת מצב הקבצים ו־Git; התיעוד אינו תחליף לבדיקת הקיים.
2. זהה את תת־המשימה היחידה שהמשתמש ביקש. הסבר בקצרה מה בונים ולמה, ובצע רק אותה. אל תתקדם אוטומטית לתת־המשימה הבאה.
3. אל תמחק או תדרוס קוד ושינויים קיימים ללא צורך. שמור על הפרדה בין שינויי המשתמש לשינויי המשימה.
4. לפני מימוש החלטה ארכיטקטונית משמעותית, הסבר חלופות והמלצה. אל תמחק החלטה קודמת: שמור את ההחלטה המקורית ותעד תאריך, סיבת שינוי והשפעה.
5. הוסף תלויות, תשתיות ושירותים חיצוניים רק כשנדרשים לתת־המשימה. השתמש בנתוני בדיקה סינתטיים בשלבי הפיתוח המוקדמים.
6. בסיום עדכן את המסמכים הרלוונטיים: PRODUCT לשינוי דרישות/תכולה, ARCHITECTURE לשינוי טכני ו־PROGRESS בכל משימה.
7. תעד מה השתנה, מה נבדק בפועל והתוצאות, מה לא נבדק ולמה, מה נשאר ומהי תת־המשימה הבאה. הרץ בדיקות, typecheck ו־build המתאימים לשינוי כאשר קיימת סביבת יישום.
8. הסבר את ההחלטות החשובות לצורך למידה. לאחר בדיקות תקינות וסקירת ההבדלים, בצע Commit מקומי לפי כללי Git שלהלן, דווח את ההודעה והמזהה ועצור עד לבקשת המשך.

### כללי Git קבועים — הוראת משתמש מ־2026-10-31

המשתמש אישר לסוכן לנהל Commits מקומיים בעצמו, והוא יבצע Push ל־GitHub ידנית. הנחיה זו מחליפה את ההנחיה הקודמת להציע הודעה בלבד; עד 2026-10-30 לא הייתה הרשאה לבצע Commit ולכן לא בוצע כזה במשימות הקודמות.

- בתחילת משימה: בדוק `git status`, ענף נוכחי, היסטוריה, Staging וקונפליקטים. זהה שינויים קיימים לפני עריכה והבחן בינם לבין שינויי המשימה.
- לאחר בדיקות רלוונטיות תקינות: עדכן תיעוד, סקור `git diff` וגם את השינוי שב־Staging, הוסף רק קבצים הקשורים למשימה ובצע Commit מקומי לפי Conventional Commits.
- אם בדיקה רלוונטית נכשלת, אין לבצע Commit עד לתיקון או לאישור מפורש של המשתמש. אין לצרף שינויים לא צפויים או קונפליקטים ללא בירור.
- אין לכלול סודות, קבצים אישיים או שינויים לא קשורים. אין להשתמש ב־`git add .` בלי בדיקה פרטנית של התכולה.
- מותר לבצע Commit מקומי על `main`. אין ליצור ענף או להחליף ענף ללא צורך מתועד ואישור המשתמש.
- אין לבצע Push, merge או rebase ללא אישור מפורש. אין לבצע force push או לשכתב היסטוריה קיימת.
- בסיום דווח ענף, הודעת Commit ומזהה, מצב עץ העבודה והאם יש Commits מקומיים שלא נשלחו. השוואה ל־remote-tracking ref ללא fetch משקפת את המצב המקומי הידוע בלבד.

המסמכים נועדו לאפשר המשכיות גם בצ'אט חדש. כדי להפנות צ'אט חדש למקור האמת, אפשר להשתמש בנוסח ההעברה שבסוף הקובץ; אין להניח שיש לו גישה להיסטוריית השיחה או לקובץ האפיון המצורף.

## 2. מה נמצא בתחילת שלב 0

- מאגר Git בשם `hireflow`, עם Commit קיים: `06aac1c Initial commit`.
- קבצים במעקב: `README.md` ובו תיאור קצר באנגלית, ו־`.gitignore`.
- `package-lock.json` קיים אך אינו במעקב Git. הוא מכיל שם פרויקט ומפת packages ריקה; נשמר ללא שינוי.
- לא נמצאו `package.json`, קוד אפליקציה, תצורת workspace, מסד נתונים, בדיקות או שלושת מסמכי התיעוד.
- לא נמצאו קובצי `AGENTS.md` בתיקיית הפרויקט או בתיקיות האב שנבדקו.
- האפיון שסופק בקובץ הטקסט המצורף שימש מקור לדרישות. הדרישות רוכזו במסמכים כדי שהמשך העבודה לא יהיה תלוי בזמינות הקובץ המצורף.

### תת־משימה 1.1 — שלד pnpm workspace

בתחילת המשימה נקראו שלושת המסמכים ונבדקו Git, מבנה הקבצים וכלי הפיתוח. המצב היה זהה לסיום 0.1: רק README ו־`.gitignore` במעקב; שלושת מסמכי `docs` וקובץ `package-lock.json` ללא מעקב. לא נמצאו הוראות `AGENTS.md` בתיקיית הפרויקט או באבות שנבדקו. הכלים הזמינים: Node `v24.18.0`, pnpm `11.9.0`.

הוסברו Monorepo, ה־workspace וההפרדה העתידית בין `apps` ל־`packages` לפני יצירת הקבצים. נוצרו:

| קובץ | תפקיד והחלטה |
| --- | --- |
| `package.json` | חבילת שורש פרטית `hireflow`, בחירת pnpm 11.9.0 ודרישות Node `>=24.18.0 <25`; ללא תלויות או scripts |
| `pnpm-workspace.yaml` | דפוסים `apps/*` ו־`packages/*`, עם `engineStrict: true` |
| `pnpm-lock.yaml` | נוצר בידי pnpm ב־offline; נעילה משותפת, כרגע ללא תלויות |
| `.nvmrc` | גרסת Node 24.18.0 לשחזור סביבת פיתוח עם nvm |

עודכנו README עם הסברים ופקודות, ARCHITECTURE עם מצב השלד והחלטות D11–D12, PRODUCT עם המצב הנוכחי, והמסמך הזה עם ההתקדמות.

`package-lock.json` הוסר רק לאחר שנבדק והוסבר למשתמש כי הוא מכיל `packages: {}` וללא תלויות. לא היה גרף תלויות להעביר; ההסרה מונעת שני קובצי נעילה לשני מנהלי חבילות. ההחלטה מתועדת גם ב־D12.

לא נוצרו תיקיות אפליקציות או חבילות ריקות. תצורת TypeScript והמהדר נדחו ל־1.2, שבה יהיה קוד לאימות. לא הוקמו React, Express, מסד נתונים, Docker, Redis, סוכן או חיבור AI. לא הותקנו תלויות ולא שונו כלים גלובליים. לא בוצעו staging או Commit; מסמכי שלב 0 עדיין לא היו במעקב בתחילת המשימה.

### 2026-10-31 — אימות חוזר וסגירת 1.1 ב־Git

המשתמש ביקש שוב את תת־משימה 1.1 והוסיף הרשאה קבועה ל־Commits מקומיים. הבדיקה הראתה שהשלד כבר קיים כפי שנוצר במשימה הקודמת; אין צורך לשחזר אותו או להוסיף תצורות. השינוי היחיד בתוכן הקבצים בסבב זה הוא עדכון PROGRESS עם כללי Git, האימות ותיעוד הסגירה. PRODUCT ו־ARCHITECTURE נשמרו ללא שינוי, כי אין דרישה או החלטה טכנולוגית חדשה.

מצב Git בתחילת הסבב: ענף `main`, Commit יחיד `06aac1c Initial commit`, README שונה ושבעה קבצים ללא מעקב — ארבעת קובצי השלד ושלושת מסמכי docs. ה־Staging היה ריק, ללא קונפליקטים. כל השינויים תואמים לעבודה הקודמת בשיחה; לא נמצאו שינויים לא צפויים. לא בוצע שינוי ענף.

לא בוצע Commit נפרד בשם `docs: document product scope, architecture, and project progress`: המשתמש התנה זאת בכך שמסמכי שלב 0 לא השתנו מאז שלב 0, אך שלושתם כבר עודכנו בעקבות 1.1. לכן אין לשמור את הגרסה הנוכחית כאילו היא תיעוד שלב 0 בלבד, ואין להחזיר קבצים לגרסה קודמת כדי ליצור הפרדה מלאכותית. מסמכי התכנון והעדכונים שלהם נכללים יחד עם השלד ב־Commit של 1.1.

ה־Commit לסגירת המשימה נקרא `chore: initialize pnpm workspace configuration`, וכולל רק את שמונת הקבצים שנבדקו: README, ארבעת קובצי הבסיס ושלושת מסמכי docs. מזהה ה־Commit נוצר לאחר שמירת מסמך זה וניתן למצוא אותו ב־`git log -1 --oneline`; בדיקת עץ העבודה שלאחר ה־Commit תדווח למשתמש בסיום. אין לבצע Push כחלק מהמשימה.

`package-lock.json` אינו קיים בתחילת הסבב הזה. הוא הוסר בסבב הקודם לאחר בדיקת תוכנו הריק, כפי שמתועד ב־D12; לא בוצעה מחיקה נוספת. קובץ כזה נוצר בדרך כלל מפעולה של npm, אך מקור הפעולה המדויק כאן אינו ידוע. לא נוצרו תלויות, תיקיות או קוד חדש, ולא התחילה תת־משימה 1.2.

### בדיקות תת־משימה 1.1

כל בדיקות התצורה הבאות עברו עם Node 24.18.0 ו־pnpm 11.9.0:

| בדיקה | תוצאה |

אין עדיין פקודות `build`, `typecheck` או `test`: אין קוד מוצר, מהדר או אפליקציה. לא הורצו בדיקות התנהגות מוצר ולא הוקמה תשתית הבדיקות של 1.4. פקודות ההתקנה והרשימה לעיל הן בדיקות התצורה המתאימות לשלב הנוכחי.
